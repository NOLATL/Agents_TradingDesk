## Decision this stage forces — indexed price table (RECOMMENDED; confirm with human)

Stage 1 deliberately avoided a `price_bars` table (`DECISIONS.md`: "Add a real table deliberately — migration 002 — if Stage 2 analytics need indexed bars"). **Stage 2 is that trigger, and the recommendation is yes:** the simulator marks 6–10 positions to market every session across a lengthening history and the controls need fast cross-sectional access (e.g. `momentum_top10` ranks a universe each rebalance). On-read JSON parsing of cached blobs will be slow and awkward for daily MTM.

**Recommended:** add migration `002_price_bars.sql` — an indexed table (`symbol`, `session_date`, raw OHLCV, adj OHLCV, `splitFactor`, `divCash`, `source_doc_hash` back-reference to the immutable `documents` row). It is a **read-through cache derived from the immutable JSON, never a second source of truth**: every bar carries the hash of the `documents` row it came from, and a test proves the table can be rebuilt bit-identically from cached documents alone. If the human prefers to defer, keep `parse_bars` on-read and revisit — but flag the performance cost.

**→ Confirm this with the human before building it. Record the ruling in `DECISIONS.md`.**

## Build order (bottom-up; each testable before the next)

### 1. Ledger core (`analytics/engine/ledger.py`)
Append-only `Trade` writes; `TaxLot` open/close with FIFO (or a documented, tested lot-selection rule — record the choice); realized P&L and holding-period computation; `wash_sale_candidate` flagging (repurchase within 30 days of a realized loss — *candidate* only, not tax-authoritative). No UPDATE/DELETE on trades. Every quantity is `Decimal`, never float.

### 2. Execution / fill model (`analytics/engine/execution.py`)
The corrected slippage direction (spec §6): **buy fills at session open + adverse slippage; sell fills at open − adverse slippage**, using **raw** Tiingo prices as of the fill date. Tiered slippage by liquidity/volatility/spread/gap/event-status, from versioned `config/` — start conservative. Record `slippage_applied` on every `Trade`. Fills occur at the **next** valid session open after approval (`exchange_calendars`), never same-bar.

### 3. Portfolio & mark-to-market (`analytics/engine/portfolio.py`)
Daily MTM of all positions → `DailyNav` (`nav`/`cash`/`positions_value`). Frozen positions mark at `frozen_mark`, not live price. Corporate actions applied deterministically from Tiingo `splitFactor`/`divCash` (splits adjust share counts on ex-date; dividends credit cash) — these are the *supported* actions.

### 4. Cluster risk budgeting (`analytics/engine/sizing.py`)
**Not** a covariance optimizer (spec §5/§6 — optimizers overfit 6–10 names). Each theme/cluster gets a fixed share of total portfolio risk; inverse-volatility within the cluster; **Ledoit-Wolf-shrunk correlations** (scikit-learn) only to *identify* clusters, not to invert. Uses the adjusted series via `volatility.py`. Output feeds proposed `Order` quantities. Enforces the §8 exposure limits (10% single name, 25% theme, 30% sector, cluster risk budget, max beta) as hard deterministic caps.

### 5. Quarantine protocol (`analytics/engine/quarantine.py`)
The full §6 sequence: unsupported/unclassifiable corporate action → **freeze-and-mark** (`Position.frozen=True`, `frozen_mark=last valid close`) → **data-integrity breaker fires** → classified `DataIncident` raised + human alerted → human resolution via a HUMAN-provenance adjustment (`resolution_assertion_id`) → **bounded-window fallback**: if unresolved past N days (config), force-liquidate at last valid close AND set `contains_forced_resolution=True` on every affected `DailyNav`/`BenchmarkNav` row. Determinism preserved; nothing silently computed.

### 6. Control benchmarks (`analytics/engine/controls.py`)
The four `BenchmarkNav` series, run **forward in-simulator on identical timing and cost assumptions** as the live book: `spy`, `equal_weight_sp500_proxy`, `momentum_top10` (rank by 12-month adjusted return, top 10 equal-weight, monthly), `same_basket_no_llm_timing` (the desk's basket, equal-weight, fixed rebalance — isolates whether LLM timing/sizing adds anything). These need the indexed bars (decision above) for cross-sectional ranking.

### 7. Four breakers (`analytics/engine/breakers.py` or `risk.py`)
Independent, deterministic (spec §8): **market-risk** (drawdown from high-water mark, EOD-only → block new risk, no forced liquidation), **data-integrity** (missing/stale/revised/inconsistent/unsupported-CA → halt order generation; drives quarantine), **operational** (incomplete pipeline/failed reconciliation/duplicate run → halt + idempotent recovery), **model-quality** (malformed/ungrounded/low-confidence output → reject proposal). Each specifies watermark, evaluation timing, block-vs-de-risk, reset condition, logged override path.

### 8. Metrics (`analytics/engine/metrics.py`)
Deterministic: Sharpe, Calmar, max drawdown, hit rate, per-`strategy_tag` attribution, and the calibration instruments — **Brier score + calibration curves** over resolved `Forecast`s (respecting exit-type decoupling: `PRICE_STOP`/`VALUATION_EXIT` don't resolve forecasts), **Probabilistic Sharpe Ratio**, block-bootstrap CIs. P&L reported as noise-level over short windows.

## Backups (wire this stage — the DB now holds real research + will hold NAV history)

Single-disk reality: the Framework has one 1TB card, so a same-disk dump protects only against *logical* failure (bad migration, corruption, accidental drop), not disk death. Offsite copy is therefore required, and the human has chosen **Google Drive via `rclone`** (existing storage, no new account, API-clean — not the Drive desktop client, not a Drive-synced folder, which race on mid-write files).

Implement:
1. **Nightly `pg_dump`** of the project DB → `gzip` → a dated file in a local backup dir on the 1TB card (logical-failure safety net; keep a rolling N days).
2. **`rclone copy`** of that *sealed* dump file to a Google Drive remote (offsite). Copy a finished file via the Drive API — never live-sync the data dir. `rclone` config/token lives outside any LLM context; document the one-time OAuth setup in `DECISIONS.md`. Claude Code may script the setup but must have the human complete the interactive Google auth step.
3. **Git remote:** push the repo to a private remote (covers code; the DB does not go in git — too large/binary/churny).
4. **Restore test (required for the gate):** restore a dump into a throwaway scratch DB (`compose.test.yaml`) and assert schema + row-count sanity. A backup that hasn't been restored is not a backup.
5. Drive the whole thing from a **systemd timer** (idempotent, per CLAUDE.md).

**Deferred to the pre-live gate (Stage 4):** revisiting the *optimal* backup architecture once everything is in place — retention policy, whether to add a second provider (R2/B2) or a second physical disk, encryption-at-rest of dumps, and offsite frequency. When real capital is at stake the calculus changes; for now, regenerable research + simulated NAV on Drive is proportionate. Record this as an explicit deferred decision.
